# Little Lives: audit and premium recovery decision

**Recommendation: approve a scoped hybrid reconstruction, not another cosmetic pass on this prototype.** Preserve useful simulation concepts and kitchen action intentions; replace the hero asset pipeline and visual presentation, and refactor task ownership/persistence before adding the family. Babylon.js is the leading browser renderer candidate, with Three.js close; confirm it through an approved imported-asset proof before committing the full production.

**Scope limitation:** the supplied materials are one 232,404-byte HTML kitchen build and a 1280×853 composite design board. No full repository, Claude QA report, separate definitive house/style originals or Blender/model assets were supplied. A connected repository-name search returned no match. This is a complete audit of the accessible runtime, not of absent code or unseen approved originals. Those gaps were disclosed before visual assessment. No redevelopment was started; the game snapshot is unchanged.

## What the evidence establishes

- The game is **one furnished kitchen**, a corridor stub, a closed dining stub and a roof cap. No bedroom, bathroom, living room, study, actual upstairs floor or staircase exists in the supplied scene.
- It starts with the broad module view, then **every start button forces Kitchen after 2.5 seconds**. The user cannot reveal a complete hidden house by zooming out.
- Naomi is the only modeled/instantiated person. Darius, Elias and Laila are relationship data rows. Bedtime hides Naomi in the corridor and restores energy numerically.
- The renderer and kitchen task pipeline are real: WebGL2 skinning, arm IK, movement, utility choices, object states, synthesized audio and basic save UI all exist. Fourteen controlled action sequences completed. This is useful prototype work, not a finished family simulator.
- Six seven-day isolated-runtime runs and four three-day **actual-browser** soaks completed without normal-run action aborts. Every tested configuration reached hygiene zero. Fixed-seed fixed-dt repeats match, but changing dt changes schedules; saves do not preserve exact continuation.
- Confirmed defects include ignored goto callbacks, calls labeled Elias updating Darius, step-index save reconstruction changing bedtime phases, invalid loads partially mutating state, incomplete abort cleanup, stale moving-chair navigation and misleading FPS/pass counters.
- Rendered Naomi shows recognizable palette/bun/floral intent, but separate primitive-based face/mitten/garment construction and limited deformation remain materially below the board's sculpted character quality. High polygon density does not solve this.
- Desktop/mobile screenshots, board comparisons, a 43.52-second normal browser recording, logs and scripts are included. Rendering used **ANGLE SwiftShader software**, not a physical GPU or mobile device. No device performance or full auditory-quality claim is made.

Exact locations: `/workspace/audit/source/naomis-kitchen.html:1648` (single room), `:1979`/`:2003` (future floors/dining stub), `:3175`/`:3177` (forced Kitchen), `:1471`/`:3037` (one character), `:2422`/`:2880` (hidden sleep), `:2741–2766` (save/load). ## Proposed approval decision

Approve or revise **Strategy B and its bounded first visual/asset proof**. Before that proof starts, supply/identify the definitive separate reference originals, source repository and Claude report where available, and agree target devices/room scope. No gate is approved by this audit. Every subsequent gate requires actual rendered evidence and explicit approval, including full house, Naomi, integrated interactions, actual floors, household functionality, family autonomy and cinematic polish.

This package can diagnose the supplied prototype and establish a concrete recovery direction now. It cannot certify a match to missing originals, validate an absent QA report or replace dedicated art production with an engine switch.
